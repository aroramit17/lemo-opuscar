# Tutorial Steps · how-to with a guiding cursor

> **Job:** teach, drive saves. **Voice:** recommended. **Loops:** no. **Length:** 25–50 s.

## 1. Essence
A clean, fictional screen (or workspace) and a cursor that shows exactly where to click, with a numbered step marker and a one-line instruction. Fast, confident, no waiting. Not a screen recording with dead time.

## 2. Look
- A stylised app/browser window drawn in code, large and centred; the active area always zoomed so its text is readable on a phone.
- Cursor with a short trail; click ripples; the target highlights with a rounded ring.
- Step marker top-left of the safe area ("2/4"); the instruction line in the lower caption band.
- If real UI is required, use screenshots the user supplied and has rights to, cropped to the relevant region.

## 3. Timing grammar
- 0–3 s: show the finished result first (the output, the cleaned inbox, the working automation), then "here's how".
- Each step: instruction on screen → cursor travels (0.4–0.7 s, eased) → click → result. Total 5–8 s per step.
- Never more than 5 steps. If it needs more, split into a series.
- Cut dead time hard: loading becomes a jump cut with a time-lapse whoosh.

## 4. Sound
Soft UI clicks, a tick on each step marker, light rhythmic bed, a satisfying chime when the result lands.

## 5. Native moves
- **Zoom-follow.** The camera pushes into the active control and releases. *Fits:* menus; settings; code; spreadsheets.
- **Step wipe.** The step number wipes and the window re-lays itself for the next screen. *Fits:* setups; recipes; configurations.
- **Shortcut flash.** Key caps appear for a combination. *Fits:* editors; design tools; OS tips.

## 6. Pitfalls
Text too small after zoom; the cursor teleporting; revealing credentials, keys or private data (use fictional data only); steps that skip the one click the viewer needs.

## 7. Variation space
Structures: *result → steps*; *mistake → fix*; *3 steps + bonus*. Endings: the result again, "save for later", a keyword to get the template.
